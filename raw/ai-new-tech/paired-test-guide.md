# Paired test（成對檢定）概念與範例指南

整理日期：2026-11-09
用途：學習 paired test 的常用概念，並在離線評估 AI（A 版 vs B 版）時當作操作清單。
證據標記：[一般知識] 統計通用做法，未另外查來源；[建議] 本文件的設計建議，尚未在你的專案驗證；[示意] 教學用的假設數字；[已驗算] 數字已用 Python（scipy）算過。
相關文件：《AB test 評估 AI 指南》（2.9 節有精簡版；power analysis、CUPED、sequential testing 見該文件）。

## 1. 一頁摘要

| # | 概念 | 一句話 |
| --- | --- | --- |
| 1 | Paired test | 同一題，A、B 都回答。比較「每一題的差」，不比兩組平均 |
| 2 | Pair（一對） | 同一題的 A 結果加 B 結果。配對的單位是題目 |
| 3 | Difference d | 每一題的 B 減 A。整個檢定都建立在 d 上 |
| 4 | McNemar test | 結果是「對 / 錯」時用。只看 A、B 不一致的題目 |
| 5 | Paired t-test | 結果是連續分數時用。檢定 d 的平均是不是 0 |
| 6 | Wilcoxon signed-rank | 分數是等級，或 d 有極端值時用。檢定看 d 的排名 |
| 7 | Sign test | 結果是「A 贏 / B 贏」時用。數誰贏的題目多 |
| 8 | 差異大小與信賴區間 | p-value 只說「像不像運氣」。信賴區間才說「差多少」 |
| 9 | ψ 與樣本數 | A、B 不一致的題目比例 ψ 越小，需要的題數越少 |
| 10 | 和其他名詞的關係 | Golden dataset 是題目；Offline 是場景；Paired test 是比較方法；護欄是額外檢查 |

**一條主線：** Golden dataset 提供題目 → A、B 各答一次（offline）→ 評審打分 → 用 paired test 比主要指標 → 檢查護欄 → 依事先寫好的規則決定。

## 2. 核心概念

### 2.1 Paired（成對）vs Independent（獨立兩組）

**是什麼：**
- Independent：A 組和 B 組是**不同的人或不同的題目**。例如線上 A/B，500 人用 A、500 人用 B。
- Paired：A、B 面對的是**同一個對象**。例如同一題，A 答一次，B 也答一次。

**為什麼要分：** 兩種設計用的檢定不同。用錯會得到錯的 p-value [一般知識]。

**用哪一種（決策表）：**

| 問題 | 答案 | 用什麼 |
| --- | --- | --- |
| A、B 是不是用**同一批**題目（或同一批人）？ | 是 | Paired test（本文件） |
| | 否（不同的人、隨機分組） | Independent 檢定（見《AB test 評估 AI 指南》2.2） |

**AI 評估中常見的 paired 情境：** [建議]
- 離線評估：同一批 golden dataset，A、B 各答一次。
- Shadow mode：同一個真實問題，同時跑 A 和 B，只有 A 的答案給使用者看。
- 並排盲測：同一個問題，評審同時看 A、B 兩個回答。
- Crossover：同一批人先用 A 再用 B。

**不適用：** 線上隨機分組，每個人只看到 A 或 B。那是 independent。

### 2.2 為什麼 paired 更準：扣掉「題目難度」的雜訊

**問題：** 題目難度差很多。簡單題 A、B 都答得好。困難題 A、B 都答得差。這種「題目本來就不同」的差異，是雜訊。

**Paired 的做法：** 每題自己跟自己比。題目難度在 B 減 A 時被扣掉了。

**它像是：** 同一位學生考兩次，比較每個人的進步。不比兩個班的平均。不同的是，這裡的「同一位學生」是同一道題目。

**小例子（12 題，評審打 0 到 100 分）[示意][已驗算]：**

| 題號 | 難度 | A | B | d = B − A |
| --- | --- | --- | --- | --- |
| 1 | 易 | 92 | 95 | +3 |
| 2 | 易 | 85 | 88 | +3 |
| 3 | 難 | 40 | 46 | +6 |
| 4 | 中 | 78 | 80 | +2 |
| 5 | 中 | 55 | 62 | +7 |
| 6 | 難 | 20 | 25 | +5 |
| 7 | 中 | 66 | 70 | +4 |
| 8 | 易 | 95 | 96 | +1 |
| 9 | 難 | 30 | 38 | +8 |
| 10 | 中 | 72 | 75 | +3 |
| 11 | 難 | 48 | 55 | +7 |
| 12 | 易 | 88 | 90 | +2 |

- A 平均 64.1，B 平均 68.3。平均差 4.25 分。
- 每題分數的標準差約 25 分（題目難度差很多）。
- **當成 independent 比較（不看配對）：t = 0.43，p = 0.67。不顯著。**
- **當成 paired 比較：12 題 B 全部比 A 高。d 的標準差只有 2.3 分。t = 6.40，p = 0.00005。非常顯著。**
- 為什麼不同：independent 看到的雜訊是「題目難度差 25 分」。Paired 看到的雜訊是「每題 B 比 A 高多少，會差 2.3 分」。雜訊小很多。

**重點：** 資料一樣，結論相反。所以設計是 paired，就一定要用 paired 檢定。

### 2.3 Difference d 與虛無假設

**Difference d：** 每一題的 B 結果減 A 結果。

**Null hypothesis（虛無假設）：** A 和 B 沒有差別。也就是 d 的平均是 0。

**流程：**
1. Step 1：每題算 d。
2. Step 2：假設 B 沒有比 A 好。
3. Step 3：問：「如果真的沒差別，只靠運氣，看到這麼大的 d 的機率有多高？」這個機率就是 p-value。
4. Step 4：p 小於 0.05，就說差異顯著。

**常見誤解：** p = 0.016 不是「B 比較好的機率是 98.4%」。它的意思是：如果 A、B 沒差別，看到這個結果的機率是 1.6% [一般知識]。

### 2.4 該用哪一種 paired 檢定

看**每一題的結果長什麼樣子**：

| 結果型態 | 例子 | 檢定 | Python |
| --- | --- | --- | --- |
| 對 / 錯（二元） | 每題答對或答錯 | McNemar test | `scipy.stats.binomtest` |
| 連續分數 | 評審打 0 到 100 分 | Paired t-test | `scipy.stats.ttest_rel` |
| 等級，或 d 有極端值 | 評審打 1 到 5 分；某一題 B 崩壞 | Wilcoxon signed-rank test | `scipy.stats.wilcoxon` |
| 勝 / 負 | 評審二選一：A 好還是 B 好 | Sign test | `scipy.stats.binomtest` |

**重要規則：** 測試**開始前**就決定用哪一種，寫進計畫。不要看完幾種的結果，再挑 p 最小的。那是 p-hacking [一般知識]。

### 2.5 McNemar test（對 / 錯）

**是什麼：** 每題只有「對」或「錯」。McNemar test 檢定 A、B 的答對率是否有差別。

**為什麼只看一部分題目：** 每題有四種可能。

| | B 對 | B 錯 |
| --- | --- | --- |
| **A 對** | 兩個都對 | **b**：A 對、B 錯 |
| **A 錯** | **c**：A 錯、B 對 | 兩個都錯 |

- 「兩個都對」和「兩個都錯」的題目，A、B 沒有差別。它們看不出誰好。
- 只有 b 和 c 這兩格有資訊。
- 如果 A、B 真的沒差別，b 和 c 應該各佔一半。檢定的問題是：b 和 c 的差距是否大過運氣。

**流程：**
1. Step 1：每題判對錯。用 question_id 對齊 A 和 B。
2. Step 2：數 b 和 c。
3. Step 3：檢定。b + c 小於約 25 時，用 exact 版（二項檢定）。大於 25 可用卡方近似。
4. Step 4：算差異與信賴區間。差異 = (c − b) / n。

**小例子（200 題）[示意][已驗算]：**

| | B 對 | B 錯 |
| --- | --- | --- |
| **A 對** | 148 | 8（b） |
| **A 錯** | 22（c） | 22 |

- A 答對 156 題（78%）。B 答對 170 題（85%）。差異 +7%。
- 兩邊結果一樣的有 170 題。不一致的只有 30 題。
- 30 題中，B 贏 22 題，A 贏 8 題。
- **McNemar exact test：p = 0.016。顯著。**
- 差異 +7%，95% 信賴區間約 +1.7% 到 +12.3%（Wald 近似）。
- **對照：** 同一份資料當成兩組獨立比較（170/200 vs 156/200），p = 0.07。不顯著。原因和 2.2 相同：170 題「一樣」的題目是雜訊，paired 不看它們。

**常見變體：** 卡方版 McNemar 公式是 (|b − c| − 1)² / (b + c)（含連續性校正）。本例卡方值 5.63，p = 0.018，與 exact 版接近。小樣本用 exact 版 [一般知識]。

```python
import numpy as np
from scipy.stats import binomtest, norm

def mcnemar_report(a_correct, b_correct):
    """a_correct, b_correct: 0/1 陣列，用 question_id 對齊。"""
    a = np.asarray(a_correct, dtype=int)
    b_ = np.asarray(b_correct, dtype=int)
    n = len(a)
    b = int(((a == 1) & (b_ == 0)).sum())   # A 對 B 錯
    c = int(((a == 0) & (b_ == 1)).sum())   # A 錯 B 對
    p = binomtest(min(b, c), b + c, 0.5).pvalue if b + c else 1.0
    diff = (c - b) / n
    se = np.sqrt(b + c - (c - b) ** 2 / n) / n
    z = norm.ppf(0.975)
    return {"n": n, "b": b, "c": c,
            "acc_A": a.mean(), "acc_B": b_.mean(),
            "diff": diff, "ci95": (diff - z * se, diff + z * se),
            "p_exact": p}
# 本例：b=8, c=22 → p_exact ≈ 0.016，diff = 0.07，ci95 ≈ (0.017, 0.123)
```

### 2.6 Paired t-test（連續分數）

**是什麼：** 每題有一個分數（例如 0 到 100）。Paired t-test 檢定 d 的平均是不是 0。

**公式（白話）：** t = d 的平均 ÷（d 的標準差 ÷ √題數）。分子是「平均進步多少」。分母是「這個平均有多不穩」。t 越大，越不像運氣 [一般知識]。

**流程：**
1. Step 1：每題算 d = B 分數 − A 分數。
2. Step 2：算 d 的平均與標準差。
3. Step 3：算 t 與 p-value。
4. Step 4：報告平均差與 95% 信賴區間。

**小例子（沿用 2.2 的 12 題）[示意][已驗算]：**
- d 的平均 = 4.25 分。d 的標準差 = 2.30 分。標準誤 = 2.30 ÷ √12 ≈ 0.66。
- t = 4.25 ÷ 0.66 ≈ 6.40。自由度 11。p = 0.00005。
- 95% 信賴區間：+2.8 到 +5.7 分。
- 結論：B 平均比 A 高約 4 分。這個差異不像運氣。

**前提：** d 大致對稱，沒有極端值 [一般知識]。題目少（例如少於 30 題）時，這個前提更重要。不符合就改用 Wilcoxon（見 2.7）。

```python
from scipy.stats import ttest_rel
r = ttest_rel(score_b, score_a)      # 兩個陣列要依 question_id 一一對應
print(r.statistic, r.pvalue, r.confidence_interval())
# 12 題範例：t ≈ 6.40, p ≈ 5.1e-05, CI ≈ (2.79, 5.71)
```

### 2.7 Wilcoxon signed-rank test（等級或有極端值）

**是什麼：** 它不用 d 的原始大小，而是把 |d| 由小到大排名，再看「正的 d」和「負的 d」的排名總和有沒有失衡。

**為什麼需要：**
- 評審打 1 到 5 分時，「差 1 分」和「差 2 分」是等級，不是精確的距離。
- 偶爾有一題 B 變得很差，一個極端的 d 會把 t-test 的平均拉歪。Wilcoxon 只看排名，不被極端值拉動。

**小例子（12 題，d 值）[示意][已驗算]：**
- d = +2, +3, +1, +2, +4, +3, +2, +1, +3, +2, +3, **−15**。
- 11 題 B 好一點。1 題 B 差很多（−15）。
- d 的平均只有 +0.92。標準差 5.1。
- **Paired t-test：p = 0.55。不顯著。**
- **Wilcoxon：p = 0.030。顯著。**
- 為什麼不同：t-test 被 −15 拉低了平均，也拉高了標準差。Wilcoxon 只把 −15 當成「最大的負排名」，不放大它。

**但要小心：**
- 不要因為 t-test 不顯著，就換成 Wilcoxon。檢定要事先決定（見 2.4）。
- 那一題 −15 是重要訊息：B 在這題崩壞了。要去看原因，例如是不是幻覺或格式錯誤。Wilcoxon 能讓你不被它誤導，但不代表可以忽略它 [建議]。
- Wilcoxon 的前提：d 的分布大致對稱 [一般知識]。
- d = 0 的題目會被排除。|d| 有很多相同值（常見於 1 到 5 分）時，scipy 會改用近似算法，p-value 略有誤差 [一般知識]。

```python
from scipy.stats import wilcoxon
r = wilcoxon(score_b, score_a)       # d = 0 的題目自動排除
print(r.pvalue)
# 上例：p ≈ 0.030
```

### 2.8 Sign test（勝 / 負）

**是什麼：** 評審對每題只回答「A 好」或「B 好」（或平手）。Sign test 數誰贏的題目多。它是 McNemar 的近親：兩者都是對「不一致的題目」做二項檢定 [一般知識]。

**流程：**
1. Step 1：每題評審選 A 好、B 好、或平手。
2. Step 2：排除平手的題目。
3. Step 3：如果 A、B 沒差別，B 贏的比例應該是 50%。檢定實際比例是否偏離 50%。
4. Step 4：報告 B 的勝率與信賴區間。

**小例子（40 題）[示意][已驗算]：**
- B 贏 26 題，A 贏 9 題，平手 5 題。
- 排除平手後剩 35 題。B 的勝率 = 26 ÷ 35 = 74%。
- **Sign test：p = 0.006。顯著。**
- 勝率的 95% 信賴區間（exact）：約 57% 到 88%。

**重點：** Sign test 只說「誰贏的題多」，不說「贏多少」。這是它的優點（簡單、不需要分數），也是它的限制。

**LLM 評審的特別提醒：** 兩兩比較時，評審有位置偏差（偏好排在前面的答案）。要把 A、B 的順序交換，各判一次，再合併 [一般知識，MT-Bench 論文有討論，詳見《AB test 評估 AI 指南》4.11]。

```python
from scipy.stats import binomtest
r = binomtest(26, 26 + 9, 0.5)       # 平手已排除
print(r.pvalue, r.proportion_ci(method="exact"))
# p ≈ 0.006, CI ≈ (0.567, 0.875)
```

### 2.9 差異大小與信賴區間（只看 p-value 不夠）

**問題：** p-value 小，只代表「不太像運氣」。它不代表差異夠大，值得改版。

**Statistical significance vs practical significance：**
- 統計顯著：不像運氣。
- 實務顯著：差異大到值得付出改版的成本。

**怎麼看：**
1. Step 1：報告差異大小（例如 +7%）。
2. Step 2：報告 95% 信賴區間（差異的可能範圍）。
3. Step 3：問：區間的**下界**，夠不夠大到值得上線？

**小例子（沿用 2.5）：**
- 差異 +7%，信賴區間 +1.7% 到 +12.3%。
- p = 0.016，顯著。
- 但下界只有 +1.7%。如果你在乎的最小差異（MDE）是 +5%，這個證據只能說「B 比 A 好」，還不能說「B 好到 +5%」。
- 題目越少，區間越寬 [一般知識]。

### 2.10 Power 與樣本數：ψ 是關鍵

**問題：** 要幾題才夠？

**Paired 設計的特點：** 所需題數不只看差異大小（δ），還看 **ψ**：A、B 結果不一致的題目比例（對 McNemar 來說就是 (b + c) ÷ n）。

- ψ 小：A、B 很相似（例如只改 prompt 的一小段）。雜訊少，需要的題數少。
- ψ 大：A、B 差異大（例如換整個模型）。雜訊多，需要的題數多。

**公式（McNemar，大樣本近似）[一般知識][已驗算]：**

```python
from scipy.stats import norm

def mcnemar_n(delta, psi, alpha=0.05, power=0.8):
    za, zb = norm.ppf(1 - alpha / 2), norm.ppf(power)
    return ((za * psi**0.5 + zb * (psi - delta**2) ** 0.5) ** 2) / delta**2
# mcnemar_n(0.07, 0.15) ≈ 238
```

**題數表（顯著水準 0.05、power 80%）[已驗算]：**

| 要偵測的差異 δ | ψ = 15% | ψ = 20% | ψ = 30% |
| --- | --- | --- | --- |
| 10% | 約 115 題 | 約 155 題 | 約 233 題 |
| 7% | 約 238 題 | 約 318 題 | 約 478 題 |
| 5% | 約 469 題 | 約 626 題 | 約 940 題 |
| 3% | 約 1,306 題 | 約 1,742 題 | 約 2,614 題 |

**規則：**
- 差異縮小一半，題數約變 4 倍。
- ψ 在測試前不知道。用過去的離線結果估計，或先小規模試跑。不確定時保守取 20% 到 30%。
- 注意：2.5 的範例有 200 題，ψ = 15%，δ = 7%。這個設計的 power 約 73%，低於 80%。題庫要加到約 240 題才達到 80% [已驗算]。這也說明了：小題庫抓不到小差異。
- 內部系統題庫常常只有 50 到 200 題。這時要接受「只能偵測較大的差異」，或增加題數、減少 ψ（一次只改一個變因）[建議]。

## 3. 如何執行 paired test（7 步）

每一步附：背景、原因、做法。

### Step 0：事先寫下規則

- **背景：** 結果出來後，人很容易重新詮釋。
- **原因：** 先看結果再訂規則，等於替自己想要的結論找理由 [一般知識]。
- **做法：** 在跑任何東西之前，寫下：
  1. 假設（把什麼從 A 改成 B，只改一處）。
  2. 主要指標與檢定（見 2.4）。
  3. 護欄指標與門檻。
  4. 顯著水準（通常 0.05）與最小有意義差異 MDE。
  5. 決策規則：「主要指標顯著變好，且護欄沒變差，才採用 B。」

### Step 1：固定題庫，每題有 question_id

- **背景：** 配對的單位是題目。
- **原因：** 沒有 ID，就無法把 A 的結果和 B 的結果配成一對 [一般知識]。
- **做法：** 用 golden dataset。題庫版本固定。分成「開發用」與「驗收用」，驗收用的題目不拿來調 prompt（見《AB test 評估 AI 指南》4.10）。

### Step 2：A、B 各回答每一題

- **背景：** AI 的輸出有隨機性。
- **原因：** 同一題跑兩次，答案可能不同。只跑一次，結果很吵 [一般知識]。
- **做法：**
  1. A、B 用相同的設定（temperature 等），除非那就是實驗變因。
  2. 如果每題多跑幾次，**先把每題的多次結果彙整成一個值**（平均或多數決）。
  3. 樣本數是題數，不是題數乘以次數。

**小例子（每題跑 3 次）：**

| 題號 | A 三次 | A 彙整（多數決） | B 三次 | B 彙整 |
| --- | --- | --- | --- | --- |
| Q7 | 對、對、錯 | 對 | 對、對、對 | 對 |
| Q8 | 錯、對、錯 | 錯 | 對、對、錯 | 對 |

- Q7：一對（對，對）。兩邊一樣。
- Q8：一對（錯，對）。B 贏。
- 200 題就是 200 對，不是 600 對。

### Step 3：評審打分，且盲評

- **背景：** 評審可能受版本標籤影響。
- **原因：** LLM 評審有位置、冗長、自我偏好偏差（見《AB test 評估 AI 指南》4.11）[來源：MT-Bench 論文，經該文件引用]。
- **做法：** 同一個評審、同一份 rubric、不標示是 A 還是 B。兩兩比較時隨機排序，或交換順序各判一次。

### Step 4：對齊成對，算 d 或 b / c

- **做法：** 用 question_id 對齊。
  - 二元結果：數 b 和 c。
  - 連續分數：每題算 d = B − A。
  - 勝負：數 B 贏、A 贏，排除平手。

### Step 5：檢定，並報告差異與信賴區間

- **做法：** 用 Step 0 事先決定的檢定（見 2.4）。報告：
  1. 差異大小（例如 +7%）。
  2. 95% 信賴區間。
  3. p-value。
  4. 題數，與不一致的題數（b + c）。

### Step 6：檢查護欄

- **背景：** 只看主要指標會被騙（見《AB test 評估 AI 指南》2.7）。
- **原因：** AI 常用「變長、變貴、變慢」換取品質 [一般知識]。
- **做法：** 逐一檢查護欄。護欄用「不能超過的門檻」來定，因為題目少時，很小的變差測不出顯著 [一般知識]。

**小例子 [示意]：**

| 指標 | A | B | 規則 | 結果 |
| --- | --- | --- | --- | --- |
| 答對率（主要） | 78% | 85% | paired test 顯著提升 | 通過（p = 0.016） |
| 每題成本 | $0.020 | $0.026 | 不超過 $0.030 | 通過 |
| 平均延遲 | 3.0 秒 | 3.4 秒 | 不超過 5 秒 | 通過 |
| 不該回答的題目被回答的比例 | 2% | 2% | 不可變差 | 通過 |

### Step 7：決策與記錄

- **做法：**
  1. 依 Step 0 的規則決定：採用 B、不採用、或需要更多題。
  2. 記錄設定、結果、結論。
  3. 看 b 那一格（A 對、B 錯）的題目。這些是 B 退步的案例，可以找出 B 的缺陷。
  4. 發現的新失敗案例加進 golden dataset。

## 4. Paired test 與其他名詞的關係

它們不是同一件事。它們回答不同的問題。

| 名詞 | 回答的問題 | 在這條流程中的位置 |
| --- | --- | --- |
| Golden dataset（黃金資料集） | 用「哪些題目」比？ | 提供題目與標準答案 |
| Offline 測試 | 「在哪裡」比？ | 用固定題庫、不用真人使用者 |
| LLM-as-judge | 「誰」打分？ | 把回答變成分數或對錯 |
| Paired test | 「怎麼判斷」差異是真的？ | 對 A、B 的每題結果做統計檢定 |
| Guardrail metrics | 還要檢查「什麼不能變差」？ | 主要指標通過後，再逐一檢查 |

**常見問題：**

| 問題 | 回答 |
| --- | --- |
| Paired test 一定要 offline 嗎？ | 不一定。Shadow mode、並排盲測也可以用。但離線同題比最自然 [建議] |
| Offline 評估一定要用 paired test 嗎？ | 如果 A、B 回答同一批題目，建議用。不用的話，會浪費題目配對的資訊 [一般知識] |
| Guardrail 能用 paired test 嗎？ | 可以。成本、延遲等也是每題一個值，可以用 paired t-test。但護欄常直接用門檻判斷 [建議] |
| Paired test 能判斷線上真實使用者的效果嗎？ | 不能。它只告訴你「在這批題目上」B 是否比 A 好。題庫不代表真實流量時，要靠線上 A/B 確認 [一般知識] |

## 5. 注意事項（陷阱）

| # | 陷阱 | 原因 | 如何避免 |
| --- | --- | --- | --- |
| 1 | 題目沒有一對一對齊 | 配對檢定的前提是同一題的 A、B 成一對。對錯了，結果沒有意義 [一般知識] | 用 question_id 對齊；比較前檢查兩邊題數相同 |
| 2 | 重複執行當成獨立樣本 | 同一題跑 5 次，這 5 次彼此相關。當成 5 題，p-value 太小，結論過度樂觀 [一般知識] | 先把每題彙整成一個值（Step 2） |
| 3 | 題目彼此不獨立 | 同一份文件問 10 題，這 10 題彼此相關，實際的 n 比 10 小 [一般知識] | 題庫分散在不同來源；或以文件為單位彙整 [建議] |
| 4 | 看完結果才挑檢定 | 試了 t-test 又試 Wilcoxon，挑 p 小的，誤判率變高 [一般知識] | 事先決定（Step 0） |
| 5 | 小樣本用卡方近似 | b + c 小於約 25 時，近似不準 [一般知識] | 用 exact 版（binomtest） |
| 6 | 只看 p-value | p 小不代表差異大 | 同時報告差異與信賴區間（2.9） |
| 7 | 題庫太小，樣本數不足 | 沒有做 power analysis，真的有差異也測不出來 | 先算題數（2.10）；題庫小就接受只能測大差異 |
| 8 | 同時比較多個指標 | 比越多，越容易有一個因運氣顯著 [一般知識] | 一個主要指標下結論；其他當護欄或探索（見《AB test 評估 AI 指南》4.3） |
| 9 | 反覆針對同一份題庫調 prompt | 每改一次、看一次分數，就多一次抽獎。這是離線版的 peeking [建議] | 分「開發用」與「驗收用」（Step 1）；驗收用的題庫只看最後一次 |
| 10 | 一次改很多變因 | 變好了不知道是哪個造成的，ψ 也變大 | 一次只改一處（Step 0） |
| 11 | 忽略 b 那一格 | 平均變好時，仍可能有些題目退步 | 檢視 A 對 B 錯的題目（Step 7） |
| 12 | Paired test 用在不同的人 | 線上隨機分組，A、B 面對的不是同一個對象 | 改用 independent 檢定（2.1） |

## 6. 完整範例（客服 chatbot 離線評估）[示意]

1. **Step 0 規則：** 把 prompt 加上「先確認訂單編號」。主要指標：答對率，用 McNemar exact test。護欄：每題成本不超過 $0.030、延遲不超過 5 秒、不該回答的題目被回答的比例不可變差。α = 0.05。規則：主要指標顯著變好且護欄通過，才進入線上。
2. **Step 1 題庫：** 200 題 golden dataset（驗收用），去識別化，標準答案由客服主管確認。
3. **Step 2 執行：** A、B 各答 200 題，每題跑 3 次，用多數決彙整。樣本是 200 對。
4. **Step 3 評審：** LLM 評審，與人工一致率 85%，盲評。
5. **Step 4 對齊：** 用 question_id 對齊。得到下表：

| | B 對 | B 錯 |
| --- | --- | --- |
| **A 對** | 148 | 8 |
| **A 錯** | 22 | 22 |

6. **Step 5 檢定：** A 78%，B 85%，差異 +7%，95% 信賴區間 +1.7% 到 +12.3%，McNemar exact p = 0.016。通過。
7. **Step 6 護欄：** 成本 $0.020 → $0.026，延遲 3.0 → 3.4 秒，不該回答的比例 2% → 2%。都通過。
8. **Step 7 決策：** 主要指標與護欄都通過，進入小流量線上 A/B。
9. **回饋題庫：** 看那 8 題「A 對 B 錯」的題目，發現 B 在「訂單編號格式不同」的題目退步。這些加入題庫的下一版，並修 prompt。

**這個結論的限度：** 下界只有 +1.7%。200 題的 power 只有約 73%。線上 A/B 才能確認真實效果（見《AB test 評估 AI 指南》3）。

## 7. 限定與待驗證

- 本文件的所有數字（分數、題數、成本、延遲）是教學用示意，不是真實專案資料。
- McNemar、paired t-test、Wilcoxon、sign test 的 p-value 與信賴區間，以及題數表，已用 Python（scipy）驗算。資料與程式在這次對話中執行過。
- 2.5 的信賴區間是 Wald 近似。小樣本時可改用 exact 或 Newcombe 方法，數字會略有不同。
- 本文件的統計內容屬通用做法，沒有另外查來源。LLM 評審偏差的說法引用自《AB test 評估 AI 指南》所列的 MT-Bench 論文。
- 2.7 的 Wilcoxon 例子（d 中有一個 −15）是刻意設計，用來說明「極端值」。不是建議用它取代 t-test。
- 「內部系統題庫常常只有 50 到 200 題」來自你先前對自己情境的描述，不是通則。
- 還沒涵蓋的進階主題：repeated-measures（每題多次結果的混合模型）、題目分群的 clustered 檢定、non-inferiority test（正式的「護欄沒有變差」檢定）、Bayesian paired 比較、bootstrap 信賴區間。
