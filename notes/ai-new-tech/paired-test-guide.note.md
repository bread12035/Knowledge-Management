# Paired test 概念與範例指南（note）

## 一句話
離線評估 A、B 兩版時，同一題兩邊都答，用每題的差做檢定；依結果型態事先選 McNemar、paired t、Wilcoxon 或 sign test，並報告差異與信賴區間。

## 主張
原文證據標記對應：[一般知識] → {討論結論}、[建議] → {我的判斷}、[示意] → {示意}；[已驗算] 的數字保留並註明。

### §2.1 Paired vs independent
- Independent 是 A、B 面對不同的人或題目；paired 是面對同一個對象（同一題 A、B 各答一次）{討論結論} (§2.1)
- 設計是 paired 就要用 paired 檢定，用錯會得到錯的 p-value {討論結論} (§2.1)
- AI 評估常見的 paired 情境：離線同題評估、shadow mode、並排盲測、crossover；線上隨機分組不適用 {我的判斷} (§2.1)

### §2.2 為什麼 paired 更準
- Paired 每題自己跟自己比，題目難度的雜訊在 B − A 時被扣掉 {討論結論} (§2.2)
- 12 題範例（已驗算）：當成 independent 時 t = 0.43、p = 0.67；當成 paired 時 t = 6.40、p = 0.00005；資料一樣，結論相反 {示意} (§2.2)

### §2.3 Difference d 與虛無假設
- p = 0.016 的意思是「若 A、B 沒差別，看到這個結果的機率是 1.6%」，不是「B 較好的機率 98.4%」{討論結論} (§2.3)

### §2.4 選哪一種檢定
- 對 / 錯 → McNemar；連續分數 → paired t-test；等級或 d 有極端值 → Wilcoxon signed-rank；勝 / 負 → sign test {討論結論} (§2.4)
- 檢定要在測試開始前決定並寫進計畫，看完結果再挑 p 最小的是 p-hacking {討論結論} (§2.4)

### §2.5 McNemar
- 只有 A 對 B 錯（b）與 A 錯 B 對（c）有資訊；兩邊一致的題目不看 {討論結論} (§2.5)
- b + c 小於約 25 時用 exact 版（二項檢定），否則可用卡方近似 {討論結論} (§2.5)
- 200 題範例（已驗算）：b = 8、c = 22，差異 +7%，95% CI 約 +1.7% 到 +12.3%，exact p = 0.016；當成兩組獨立時 p = 0.07 {示意} (§2.5)

### §2.6–2.8 其他檢定
- Paired t-test 檢定 d 的平均是否為 0；前提是 d 大致對稱、沒有極端值，題目少於 30 題時更重要 {討論結論} (§2.6)
- Wilcoxon 用 |d| 的排名，不被單一極端值拉動；範例中 t-test p = 0.55、Wilcoxon p = 0.030（已驗算）{示意} (§2.7)
- 不可因為 t-test 不顯著就換 Wilcoxon；極端的負 d 是 B 崩壞的訊號，要去看原因 {我的判斷} (§2.7)
- Sign test 排除平手後檢定 B 的勝率是否偏離 50%；只說誰贏得多，不說贏多少 {討論結論} (§2.8)
- LLM 評審兩兩比較時有位置偏差，要交換 A、B 順序各判一次再合併 {討論結論} (§2.8)

### §2.9 差異大小與信賴區間
- p-value 只說「像不像運氣」；要同時報告差異大小與 95% 信賴區間，並看下界是否超過 MDE {討論結論} (§2.9)
- 範例 CI 下界 +1.7%，若 MDE 是 +5%，只能說 B 比 A 好，不能說好到 +5% {示意} (§2.9)

### §2.10 Power 與 ψ
- Paired 設計的所需題數由差異 δ 與 ψ（A、B 結果不一致的比例）決定 {討論結論} (§2.10)
- δ = 7%、ψ = 15% 約需 238 題；δ = 5%、ψ = 20% 約需 626 題（已驗算）{討論結論} (§2.10)
- 差異縮小一半，題數約變 4 倍；ψ 事先不知道時保守取 20% 到 30% {討論結論} (§2.10)
- 200 題、ψ = 15%、δ = 7% 的 power 只有約 73%（已驗算）{示意} (§2.10)
- 內部題庫常只有 50 到 200 題，只能偵測較大差異，或增加題數、一次只改一個變因以降低 ψ {我的判斷} (§2.10)

### §3 執行 7 步
- Step 0 事先寫：假設（只改一處）、主要指標與檢定、護欄與門檻、α 與 MDE、決策規則 {討論結論} (§3)
- 題庫每題要有 question_id，分「開發用」與「驗收用」，驗收用的不拿來調 prompt {討論結論} (§3)
- 每題多跑幾次時，先彙整成每題一個值；樣本數是題數，不是題數乘以次數 {討論結論} (§3)
- 評審用同一個評審、同一份 rubric、不標示版本 {討論結論} (§3)
- 護欄用「不能超過的門檻」，因為題目少時小的變差測不出顯著 {討論結論} (§3)
- 決策後要看 b 格（A 對 B 錯）的題目找出退步案例，並把新失敗案例加進題庫 {討論結論} (§3)

### §4 與其他名詞的關係
- Golden dataset 回答用哪些題目；offline 回答在哪裡比；LLM-as-judge 回答誰打分；paired test 回答差異是不是真的；guardrail 回答什麼不能變差 {討論結論} (§4)
- Paired test 只說明「在這批題目上」B 是否較好；題庫不代表真實流量時要靠線上 A/B 確認 {討論結論} (§4)

### §5 陷阱
- 反覆針對同一份題庫調 prompt 是離線版的 peeking {我的判斷} (§5)
- 同一份文件出的多題彼此相關，實際 n 比題數小；題庫要分散來源或以文件為單位彙整 {討論結論} (§5)
- 一次改很多變因會讓 ψ 變大，也無法歸因 {討論結論} (§5)
